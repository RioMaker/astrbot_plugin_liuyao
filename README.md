# astrbot_plugin_liuyao

面向 QQ 群（OneBot v11 / aiocqhttp）的六爻起卦插件。支持两条等价命令入口、即时天机、手动铜币或卦名起卦、按术数分别保存的群开关，以及 AstrBot Agent Tool。

## 功能

- 双入口：`/六爻 ...` 与 `/起卦 六爻 ...` 功能完全相同；可直接在根指令后填写问卦内容。
- 即时起卦：用系统安全随机源模拟每爻三枚铜币，保持 6/7/8/9 的 1:3:3:1 概率。
- 手动起卦：
  - 接受六个 6/7/8/9；
  - 接受六组三枚铜币字符；
  - 接受 `乾`、`乾为天`、`天风姤`、`第1卦`、`䷀` 等卦名，按无动爻静卦处理。
- 离线古籍：内置文王卦序 64 卦、64 条卦辞和 384 条基础爻辞；乾、坤另保留用九/用六。`najia.py` 按八宫、纳甲地支和五行生克计算每爻六亲。
- 意图方向：综合、事业、感情、财富、学业、健康、家庭、出行、射覆、天气；每类配套独立离线研判参考。
- 分术数开关：保存结构为“群 → 术数 → 状态”；当前只有六爻，后续增加其他术数不会共用同一个开关。
- 权限：QQ 群主、QQ 群管理员和 AstrBot 管理员都可以设置本群术数开关。
- Agent 调用：临时子 AI 独立解卦，插件直接发送排盘图和解读正文，主 Agent 只收到执行状态和简短结果摘要；追问沿用原卦并追加存档。

## 完整排盘字段（0.11.0，第一阶段）

0.11.1 优化排盘图：采用米白底、深玉绿标题和宋体卦名；六神、伏神、本卦、世应、之卦独立对齐。六亲纳甲文字按所在爻五行着色，不显示额外颜色图例；动爻使用淡朱底、侧线及动爻符号。长问题、多个动爻和完整射覆分析自动扩展图片高度。标题字体随插件内置，来源及许可见 [字体说明](assets/fonts/README.md)。

0.11.2 为四柱天干、地支分别按五行着色，月建、日辰、旬与旬空中的干支沿用此规则；六神使用协调的独立配色，白虎采用可读的银灰色。背景加入低不透明度的水墨竹纹，文字与动爻标记仍在前景；不新增颜色图例。竹纹为随插件内置的透明素材，缺失时降级为纯色背景，见 [素材记录](assets/README.md)。

新增年月日时干支、节气月建、日辰、旬与旬空、逐爻六神及世应、纳甲天干、伏神候选。图片、文字、Agent 短评与完整解读共享同一份排盘；新起卦的最近原卦和完整卦例均保存快照，复解或重绘不改用查看当天的干支。

- 统一北京时间 UTC+8；立春交接换年、节气交接时刻换月、零点换日，不采用 23 点换日或真太阳时。
- 伏神按本卦缺失六亲从本宫首卦列出；世应只标本卦；之卦六亲沿用本卦宫五行。未自动判断旺衰、用神或应期。
- 新增依赖 `lunar_python==1.4.8`，升级时需在 AstrBot 所用 Python 环境安装本插件 `requirements.txt` 并重载。依赖不可用时仍可起卦，日月干支、旬空与六神明确标“未计算”。
- 旧卦例无快照但有带时区原时间时按原时间补算展示，不修改原断；时间缺失或不带时区时不猜干支。日历支持范围为 1900–2100 年。

规则来源、边界和分阶段进度见 [排盘说明](docs/PAIPAN.md)。本阶段完成本地验证后交由 QQ 实测，再继续下一阶段。

## 临时子 AI 与群内串行执行（0.12.0）

主 Agent 调用 `cast_liuyao` 后，由插件取得当前会话模型服务，创建一次独立的临时解读请求。只传入本次问题、原盘、对应分类参考及古籍笔记、相关卦例；不传入主 Agent 的会话历史、人格或工具列表，不创建常驻群 Agent。模型一次生成完整正文和 1–3 句结果摘要，插件直接发正文并存档，主 Agent 只接收最多 180 字的结果摘要及程序核实的执行状态。

`reuse_liuyao(case_id, question)` 同样交由临时子 AI 解析本人在本群的原卦。`question` 传入追问和用户已明确补充的背景，`case_id` 支持三位编号或完整 ID；留空用于明确指向最近一卦的追问。有多条历史卦例且无法确定目标时，需先确认编号。支持 `/六爻 解读 001 对方口头答应了，接下来怎么办`；省略编号复解本人本群最近原卦。

- 每群始终最多执行 1 个任务，默认最多再等待 2 个；等待期间不创建模型请求、不生成新卦、不扣次数。
- 全插件默认最多执行 2 个任务，运行与等待总数上限为 32。默认等待 30 秒；队列满或等待超时明确返回繁忙。
- 普通命令也经过同一执行通道，防止射覆的模型调用与 Agent 解读并发。普通非射覆起卦命令仍以排盘图为输出；`/六爻 解读` 执行完整子 AI 解读。
- 任务结束、超时、取消或插件卸载时释放名额；排队期间关闭群开关会在执行前再次拦截。并发配置重载后生效。
- 同一消息事件重复调用相同工具参数复用执行回执，避免重复发送和计次；新消息中的追问可以再次执行。

单条卦例版本为 4：保留首次 `analysis` / `verdict`，新增 `summary` 和带时间的 `followups`。追问最多保留最近 20 条，每次解读加载这 20 条摘要及最近 2 条完整追加分析；原断不被追问或用户揭晓改写。管理员卦例详情可查看追加记录。新原卦增加独立 `cast_id`，避免以相近时间和相同爻值错误关联；旧数据按原时间、问题和爻值兼容匹配。原有完整卦例保留上限继续生效。

关闭卦例库后不创建完整库记录，但准入记录里的本人最近原卦仍保存初次解读和最近 20 条追问，以支持复解；起新卦时该最近原卦被替换。每用户滚动一小时 3 次、群开关、跨群隔离及五行数字卦独立规则保持有效。

子 AI 默认生成超时 90 秒，包含模型服务查找；图片失败时直接发送文字排盘。空正文、模型错误、超时或无效 JSON 不写成成功分析，也不把长正文交给主 Agent 补写；原卦已保留，可以复解。解读先存档再发送，发送异常只报告“发送未确认”，不自动重发以免重复。摘要缺失、超长或含明显格式指令时改用固定简短说明，不截取完整正文作为摘要。

不再注册 `on_agent_done` 抓取主 Agent 最终回复或自动补解，避免普通聊天被当作分析保存。旧版本“断语”要求已从工具描述和返回正文中移到临时解读请求；更新需重载插件以刷新工具说明。既有主会话中残留的旧指令不会自动清除；观察普通聊天时可用新会话对照，插件不会自行删除历史。

模型与群消息传输仍受 AstrBot 外层工具超时约束；若外层先取消，子任务会被取消并释放名额，已生成的原卦仍可复解。只调用当前已配置的模型服务，不另建 API 服务或密钥。

## 指令

两种写法完全等价：

```text
/六爻 <问卦内容>
/起卦 六爻 <问卦内容>
/六爻 [方向] <问卦内容>
/起卦 六爻 [方向] <问卦内容>

/六爻 即时 [方向] <具体问题>
/起卦 六爻 即时 [方向] <具体问题>

/六爻 手动 <六爻或卦名> [方向] <具体问题>
/起卦 六爻 手动 <六爻或卦名> [方向] <具体问题>

/六爻 开
/六爻 关
/六爻 状态
/起卦 六爻 开|关|状态

/六爻 help
/起卦 六爻 help
```

示例：

```text
/六爻 开
/六爻 今年是否适合换工作
/六爻 事业 今年是否适合换工作
/起卦 六爻 感情 这段关系该如何推进
/六爻 即时 事业 今年是否适合换工作
/六爻 手动 7 8 9 6 7 8 感情 这段关系该如何推进
/六爻 手动 正反反 正正反 正正正 反反反 正反反 正正反 财富
/六爻 手动 乾为天 事业 这个项目应该如何推进
/起卦 六爻 手动 天风姤 综合 目前局势该怎么看
```

根指令后的首个词若是受支持的方向（如 `事业`、`感情`），插件会将其识别为意图；否则保留整段问题并按关键词分类，无法识别时回落“综合”。显式具体方向优先；既有射覆识别优先级保持不变。`即时`、`手动`、`开`、`关`、`状态`、`help` 等保留子命令继续有效。

## 古籍学习笔记与任意专题查阅（0.9.0）

新增 [docs/study 学习目录](docs/study/README.md)、[基础笔记](docs/study/foundations.md)、[来源与校勘](docs/study/sources.md)，以及十份专题，每类 3 个独立古书事件，共 30 例。每例含原问、时日、本变卦与关键爻、原断短摘、书载结果、现代分析和限制。同一事件的复占不重复计数，缺失信息不补造；原断错误、应期不符及后验解释均保留。

Agent 新工具 `lookup_liuyao_reference(topic="")` 返回目录；`topic="射覆"`、`topic="天气"`、`topic="career"` 等返回任一专题全文及出处，不受本次起卦方向限制，也不要求先起卦。支持 `topic="基础"`、`topic="来源"`。一次一篇，可连续跨类型调用；仅在已开启六爻的群可用，无需管理员，不读取用户卦例数据。

原有 `data/references` 仍为自动注入的简版，新目录为按需扩展正文，重载插件后缓存更新。资料缺失明确返回未加载，不妨碍起卦。文档以《增删卜易》为纳甲主线，射覆另明确区分《金楼子》《梅花易数》例与《火珠林》规则；未声称穷尽古籍或完成刻本影像校勘。古例不导入群 KV 库，管理员卦例命令与图片发送行为不变。

## 天气与分类参考（0.8.0）

```text
/六爻 天气 明天上午杭州会下雨吗
/六爻 明天上午杭州会下雨吗
/起卦 六爻 手动 7 8 9 6 7 8 天时 明天杭州是否转晴
/六爻 卦例 天气
/六爻 卦例 事业 2
```

“天气/天时/气象/晴雨/weather”是同一方向。自然问题识别晴雨、降雪、风云等常见表达，不按单个“风/雨/雪”字触发。关键词不是完整语义理解；混合问题可显式指定方向，Agent 可根据完整上下文传入具体方向。未指定方向且检测到天气时固定天气，避免短评模型将其误改为事业等类别。

临时子 AI 的输入包含当前卦象、卦爻辞及 **通用规则＋当前类型参考正文**；主 Agent 的 `cast_liuyao` 返回只含摘要与执行状态。所有十类均已覆盖；短评生成也附匹配参考。资料索引见 [分类参考](data/references/README.md)，天气重点文档见 [天气研判](data/references/weather.md)，来源短摘、争议和待校勘项见 [候选区](docs/candidates/WEATHER_SOURCES.md)。运行时读取本地 Markdown，不联网检索，不额外调用新模型服务。

天气输出侧重地点与时段、晴雨、风云/雷电、变化先后和主反证，不套“成败吉凶”模板。缺地点/时段时要求 Agent 询问；不杜撰毫米数、温度、概率和精确时辰。0.11.0 已补日月干支、月建、旬空、伏神等排盘字段；月破、暗动、旺衰与应期尚未自动计算。

保持原输出模式：普通天气指令仍发排盘图（失败才发文字），不因此新增自动长篇解卦；经 Agent 起卦时由临时子 AI 读取对应参考并直接发送解读，沿用卦例存储。射覆原有命令分析与自动揭晓记录保持不变。天气反馈仍通过现有 Agent 反馈工具保存，没有新增天气群消息监听。天气历史参考只检索天气类，避免同卦的婚恋或射覆答案混入。

管理员可用 `/六爻 卦例 <方向> [页码]` 筛选现有已存卦例，仍只有 AstrBot 管理员可用，范围仍为当前群；开关和图文详情权限不变。没有自动生成或导入虚构“已验证天气卦例”。

六爻输入顺序固定为初爻到上爻，即自下而上。铜币记法约定为：

- 正 / 字 / 阳 / H = 3
- 反 / 花 / 阴 / T = 2
- 合计 6=老阴、7=少阳、8=少阴、9=老阳

直接输入卦名时没有手摇动爻信息，因此插件会用少阴/少阳构造静卦，并明确标记“手动指定卦名（静卦）”。

## Agent 用法

用户向主 Agent 表达具体六爻起卦需求，或对既有卦例追问。主 Agent 使用以下工具：

- `cast_liuyao(mode, intent, question, manual_lines, agent_name)`：起卦并委托临时子 AI 解读；直接发图和正文，返回摘要。
- `reuse_liuyao(case_id, question)`：委托临时子 AI 复解本人本群原卦，传入本次追问；不重新起卦、不扣次数。
- `lookup_zhouyi_text(hexagram, line)`：核对卦辞或某一爻原文。
- `lookup_liuyao_reference(topic)`：按需查阅任意专题笔记、古籍卦例及出处；留空列目录。
- `search_liuyao_cases(query, intent, hexagram, limit)`：查询已有卦例，确认追问或反馈对应编号。
- `record_liuyao_feedback(feedback, case_id, outcome, answer)`：补录本人在本群的实际结果；与子 AI 推断分开存储。

`cast_liuyao` 执行顺序：获取群内与全局执行名额 → 校验具体问题和起卦额度 → 保存新卦及原盘快照 → 生成图中短评并发送排盘 → 创建卦例、加载参考 → 临时子 AI 解读 → 保存分析并直接发送正文 → 返回简短摘要。默认图中短评和完整解读各调用一次当前会话模型，均在同一个群执行名额内串行完成。

`reuse_liuyao` 按本人、本群和指定卦例加载原盘、原断、追问及反馈，使用独立临时上下文继续解读。主 Agent 不承担解卦正文转发，也无需重复解读；普通聊天不调用六爻工具、不沿用解卦格式。

工具在已开启六爻的 QQ 群使用。天气与射覆采用各自的分析要求，所有完整解卦格式要求仅放入临时子 AI 输入。

## 卦例库

### 射覆（0.7.0）

支持 `/六爻 射覆 盒子里是什么`、`/起卦 六爻 射覆 盒子里是什么`，
以及 `/六爻 手动 乾 射覆 盒中何物`。也可以请 Agent “为我射覆，猜盒中物品”。
Agent 工具可显式传 `intent="shefu"` 或 `intent="射覆"`。

射覆分析逐项说明颜色、材质、软硬、形状与大小、用途和关联信息，结合卦象、
六亲及爻辞解释依据，再按匹配程度给出 2–4 个具体物品和首选断语。
属性依据不足时标注待验证。普通射覆指令调用当前会话模型生成完整分析并放入图中；
模型失败时明确标记分析未生成，仍保留排盘以供后续解读。

射覆卦例独立以 `intent=shefu` 分类，参考检索只取射覆记录，保存原六爻、问题、
原预测、用户揭晓答案和带时间的反馈。预测与实际答案分开保存，不会用答案修改原预测。
当前模型的实际措辞仍受模型能力与会话设定影响。

出题人无须 @机器人，在原群发送以下明确揭晓语句即可自动归档：

```text
答案是：红色橡皮球
谜底是钥匙
揭晓：塑料杯
射覆答案 001 苹果
```

只接受同群、同一出题人的反馈；其他群友的答案不会写入该卦例。存在多条待揭晓记录时，
机器人提示补充编号。重复反馈去重。普通聊天中含糊的“是它”“猜的是不是……”不会自动
作为答案；可请 Agent 查询原卦例后，使用 `record_liuyao_feedback` 的 `answer` 参数补录
用户明确给出的物品。揭晓只记录事实，不自动宣称应验。群开关或卦例库关闭时不自动归档。

### 管理员查询

以下两种入口等价；查询仅限 **AstrBot 管理员**，QQ 群主或群管理员身份本身不授予查询权限。
查询范围为当前群，群起卦开关关闭时仍可查看历史记录。

```text
/六爻 卦例                # 本群全部卦例清单，每页 20 条
/六爻 卦例 列表 2         # 第二页
/六爻 卦例 射覆           # 本群射覆卦例库
/六爻 卦例 射覆 2         # 射覆库第二页
/六爻 卦例 001            # 指定卦例详情：原卦图、原分析、用户答案和反馈
/起卦 六爻 卦例 001
```

编号至少显示三位（001、002……），旧卦例自动补号并持久化；保留上限触发后也不会复用
已淘汰记录的编号。图使用保存的原始六爻、起卦人及起卦时间重新渲染，不会重新起卦。
图发送失败时返回原始排盘和反馈文字。查询清单权限不影响 Agent 在断卦过程中内部检索参考。

卦例使用 AstrBot 插件 KV 持久化，记录问题、方向、本卦与之卦、六个爻值、动爻原文、卦宫六亲、AI 分析、最终断语及后续反馈。每次 Agent 起卦都会自动建档；临时子 AI 生成后直接保存正文和摘要，追问追加保存，不依赖主 Agent 最终回复。

用户日后提到原事情的进展或结果时，Agent 应先用 `search_liuyao_cases` 确认对应卦例，再调用 `record_liuyao_feedback`。不知道编号时，反馈工具可匹配该用户在本群最近的一例。反馈只允许当前用户更新自己在当前群的卦例。

历史参考默认严格按群隔离。若开启 `case_library_cross_group`，检索可参考其他群卦例，但返回给 Agent 的摘要不包含起卦人昵称、QQ 或群号。已有实际反馈的卦例会获得更高相关度，但当前卦象始终是主要依据。

## 安装与配置

把本目录放入 AstrBot 的 `data/plugins/`，在 WebUI 重载插件。最低 AstrBot 版本为 4.24.0；运行时依赖 Pillow 与 lunar_python==1.4.8，AstrBot 会根据 `requirements.txt` 安装。插件已内置 Noto Sans CJK SC 字体，因此 Linux/Docker 宿主机无需另外安装中文字体；字体按 SIL Open Font License 1.1 分发，许可证见 `assets/fonts/LICENSE.txt`。

配置项：

- `default_enabled`：各术数在新群中的默认状态，建议保持 `false`。
- `allow_operator_api_lookup`：原始事件缺少 `sender.role` 时，读取 OneBot 群成员资料核验群主/群管理员。
- `max_question_length`：问题最大长度。
- `case_library_enabled`：是否自动保存 Agent 六爻卦例，默认 `true`。
- `case_library_max_records`：全插件卦例上限，范围 20–5000，默认 500。
- `case_reference_limit`：每次起卦最多返回的相关卦例数，范围 1–5，默认 3。
- `case_library_cross_group`：是否允许匿名跨群参考，默认 `false`。
- `agent_send_chart_image`：Agent 起卦时是否先发送排盘图，默认为 `true`。
- `command_send_chart_image`：普通六爻指令是否先发送排盘图，默认为 `true`。
- `agent_generate_chart_comment`：是否使用当前会话模型生成图中短评并补全缺失方向，默认为 `true`。
- `agent_display_name`：Agent 没传入自身名字时使用的默认短评署名。
- `agent_comment_timeout_seconds`：短评生成超时，范围 5–90 秒，默认 45 秒。
- `agent_analysis_timeout_seconds`：临时子 AI 完整解读超时，范围 10–180 秒，默认 90。
- `subai_max_concurrency`：全插件执行上限，范围 1–8，默认 2；同群固定最多 1 个。
- `subai_group_queue_limit`：每群等待上限，范围 0–5，默认 2。
- `subai_queue_timeout_seconds`：等待名额超时，范围 5–120 秒，默认 30。
- `chart_font_path`：可选中文 `.ttf`/`.ttc`/`.otf` 字体绝对路径；留空或路径无效时使用插件内置 Noto Sans CJK SC。

## 说明

本插件以传统六爻纳甲体系为基础整理卦象、爻辞、六亲与变卦信息，解读应紧扣所问、明辨动静与时位。


## 问卦规则（0.10.0）

- 无事不卜：须有具体所问；空问题、只写方向、随便看看、消遣或测试不予起卦。Agent 不得替用户编造事由。
- 同一 QQ 用户在滚动 60 分钟内最多起卦 3 次，跨群共享，即时、手动、命令与 Agent 工具共用额度。拒绝请求不计次；有效卦记录保存后计次，即使图片或后续 AI 解读失败也可复用原卦，不再重起。
- 同一事情禁止连续起六爻卦，不能通过更换六爻起卦方式或要求重新解读来重摇。记录持久化到插件 KV，重载不清零。上一事记录不随小时额度到期而消失；换问其他具体事情后更新。
- `/六爻 解读`（或 `/起卦 六爻 解读`）由临时子 AI 解读本人最近原卦；Agent 使用 `reuse_liuyao(case_id, question)` 转交追问，不消耗次数。原卦仅在原群返回。更早卦例沿用历史检索工具。
- 本地校验拦截常见无事表述和规范化后相同的问题（忽略空白、标点、全半角与大小写）。自然语言同义改写由 Agent 结合上下文辨别并复用原卦；本地文本规则不能保证识别所有同义表达。古籍查询、历史检索和反馈不受起卦次数限制。


## 与五行数字卦隔离（0.10.1）

六爻的每小时 3 次、同一事项连续起卦限制及原卦复解，只依据本插件的六爻记录。五行数字卦的结果、次数、三次死卦及停问提示不计入六爻，也不阻止同一事项首次起六爻卦。Agent 必须区分术数：用户只测过五行数字而现在要求六爻，应调用 `cast_liuyao`，不能因“此前已占过”拒绝，也不能用五行数字结果代替六爻原卦。

两插件数据仍各自保存，没有互相读取、修改或清空；五行数字卦也不能重置已有六爻额度或使六爻重复起卦放行。更新后需重载两个插件以刷新工具说明；旧对话中的笼统停问提示应以本节规则为准。
