# 六爻卦例导出说明

## 文件与导出范围

从 AstrBot WebUI 侧栏打开「六爻起卦」，在管理页顶部选择导出范围。文件名中的时间采用北京时间（UTC+8）。

| 操作 | 收录范围 | 下载文件名 |
| --- | --- | --- |
| 导出全部卦例 | 当前库中所有群、用户及状态的卦例 | `liuyao_cases_YYYYMMDD_HHMMSS.zip` |
| 仅导出已反馈卦例 | 所有群和用户中，符合管理页「已反馈」条件的卦例 | `liuyao_cases_feedback_YYYYMMDD_HHMMSS.zip` |

一条卦例只要有一条正式反馈对象（`feedback[]`），且这条反馈的 `valid` 未被标为 `false`，就算「已反馈」。旧版缺少该字段的反馈也计入。仅有审核对话或被驳回反馈的卦例会跳过。

筛选只作用于卦例数组。编号高水位、累计积分等库级数据沿用全库值。没有符合条件的卦例时，导出的卦例数组为空。

每个 ZIP 含两个 UTF-8 文件。

| 文件 | 用途 |
| --- | --- |
| `liuyao_case_library.json` | 从插件 KV 键 `liuyao_case_library` 取得的卦例和库级数据。「导出全部卦例」保留该键的完整值。 |
| `README.md` | 本说明，解释变量名、数据结构和实际存储逻辑。 |

两种导出均独立于管理页列表的搜索、分页和筛选。卦例库关闭后，已有数据仍可导出。
被容量淘汰或管理员删除的卦例不在当前库存中，因此无法通过本次导出找回。

导出时持有卦例读写锁读取一份独立快照，然后释放锁，在后台线程中打包。
下载期间发生的新起卦、分析或反馈更新不包含在已取得的快照中，可再次导出获取。
导出不会调用模型，也不会写回、清理、重新编号或升级原数据。
ZIP 在内存中生成，不在插件静态资源目录或服务器数据目录留下导出副本。

两种导出均按原顺序保存入选卦例的全部字段，包括嵌套数据和未知扩展字段。
以下结构是当前正常写入的格式。历史数据可能缺少部分字段，也可能直接是卦例数组（此时数组元素相当于 `cases[]`），导出时沿用原有格式。
KV 键尚不存在时，输出下方空库结构，不创建数据库记录。

## 顶层结构

```json
{
  "schema_version": 2,
  "cases": [],
  "next_serial": 1
}
```

| 变量名 / 路径 | 类型 | 含义 |
| --- | --- | --- |
| `schema_version` | 整数 | 整个卦例库的结构版本，当前为 `2`，与插件版本、单条卦例版本不同。 |
| `cases` | 对象数组 | 所选范围内的完整卦例，按库中原有顺序排列。 |
| `custom_directions` | 对象，可选 | 自建分类的稳定键对应其名称 `label`、适用范围 `description` 和参考资料方向 `reference`。 |
| `next_serial` | 整数 | 下次分配的全库编号，至少为现存最大编号加一，并保留历史高水位；删除或淘汰记录不会主动回退。 |
| `user_scores` | 对象，可选 | 用户 ID → 累计审核有效反馈次数。每条卦例成功通过一次审核后加一，与预测是否应验无关。 |
| `valid_feedback_events` | 对象，可选 | 用户 ID → 有效反馈时间字符串数组，供时间窗口内的反馈奖励统计使用。同一时刻的不同卦例可有重复时间，不能去重。 |

`user_scores` 和 `valid_feedback_events` 是同一个 KV 值中的累计数据，不要求与当前
`cases` 逐条对应：卦例淘汰或删除后，既有统计可能继续保留。事件账本在新增该用户有效反馈时，
筛选保留最近 3650 天且不晚于当时当前时间的可解析时间；累计分数不随这一筛选扣减。
某用户没有独立事件账本时，时间窗口统计可从保留的有效反馈回算；累计分数只读取
`user_scores`，缺失时按零处理。因此不要仅由现存卦例数推算累计值。

## 单条卦例 `cases[]`

| 变量名 | 类型 | 含义 |
| --- | --- | --- |
| `schema_version` | 整数 | 单条卦例结构版本，当前新建记录为 `4`。 |
| `id` | 字符串 | 稳定卦例标识，通常为 `LY-YYYYMMDD-xxxxxxxx`，末段为随机标识。 |
| `serial` | 整数 | 全库递增的用户可见编号；界面或指令中可能显示为 `001`，JSON 中仍是整数 `1`。历史记录可能尚未分配。 |
| `created_at` | 字符串 | 原始起卦时间，ISO 8601 格式。 |
| `recorded_at` | 字符串，可选 | 实际调用（录入）时间，ISO 8601 格式。管理页以此倒序排列卦例；旧记录缺失时回退到 `created_at`，同一时刻按编号倒序。 |
| `updated_at` | 字符串 | 创建、保存分析、正式反馈或管理员备注时写入的更新时间；不是所有内部更新都修改它，例如审核会话保存。 |
| `group_id` | 字符串 | 所属群 ID；没有群标识时可为空字符串。 |
| `origin` | 字符串 | AstrBot 统一消息来源 `unified_msg_origin`，用于表示平台和会话来源。 |
| `caster_id` | 字符串 | 起卦用户 ID，QQ 场景为 QQ 号；按字符串读取，避免精度丢失。 |
| `caster_name` | 字符串 | 起卦时记录的用户显示名。 |
| `intent` | 字符串 | 问卦方向键，见下方映射。 |
| `intent_label` | 字符串 | 保存时的方向中文显示名。 |
| `intent_correction` | 对象，可选 | 人工改类前最初的分类键、名称（`original_intent`、`original_label`），以及最近改类账号和时间（`by`、`at`）。当前分类以 `intent`、`intent_label` 为准。 |
| `question` | 字符串 | 保存的原问题。 |
| `method` | 字符串 | 起卦方法的显示名称。 |
| `cast` | 对象 | 原始六爻值、卦象、卦爻辞、六亲和排盘快照，见下一节。 |
| `analysis` | 字符串 | 已保存的原分析全文；尚未完成解卦或仅排盘时可为空。 |
| `verdict` | 字符串 | 从分析中的「断语：」行提取的结论，最多 300 字；没有匹配行时为空。 |
| `answer` | 字符串 | 射覆揭晓的真实物品答案；普通问卦或尚未揭晓时通常为空。 |
| `feedback` | 对象数组 | 正式保存的反馈。当前每例最多闭环一次，历史数据可能有多条。 |
| `status` | 字符串 | `chart_only`：纯排盘；`awaiting_analysis`：等待分析；`analysis_unavailable`：未取得有效原断；`analyzed`：已保存原断；`feedback_recorded`：已反馈。 |
| `feedback_review` | 对象，可选 | 本例独立反馈审核会话，包含审核提示词、最近上下文和最后决定。 |
| `legacy_rejected_feedback` | 对象数组，可选 | 历史版本保存的无效反馈，在新反馈通过并写入时转存于此，便于保留历史。结构同反馈项。 |
| `admin_note` | 字符串，可选 | 管理员备注，最多 2000 字，不覆盖原分析。 |
| `admin_updated_by` | 字符串，可选 | 最近一次保存备注或人工改类的 Dashboard 登录用户名。 |

方向键：`general` 综合、`career` 事业、`relationship` 感情、`wealth` 财运、
`study` 学业、`health` 健康、`family` 家庭、`travel` 出行、`lost_item` 寻物、`shefu` 射覆、`weather` 天气。自建分类使用以 `custom_` 开头的键。
实际显示名以保存的 `intent_label` 为准。

时间字符串通常包含时区偏移，按其自身偏移解析；排盘历法统一换算北京时间。
历史时间若没有时区，不应擅自将其认定为 UTC。缺失字段不等于数值零，也不代表模型从未调用。
反馈是否闭环由 `feedback` 中是否存在 `valid` 不为 `false` 的记录判断，不能只看 `status`。


## 0.37.0 新增记录与解读历史

`created_at` 继续表示原起卦时间；`recorded_at` 是实际录入时间。`time_source` 为 `specified`（手动指定原时间）、`received`（采用收到指令时的北京时间）或 `automatic`（原有自动起卦）。`execution_mode` 区分 `chart` 与 `ai`，`retained_at` 为最近开始 AI 请求的时间，用于容量管理。`token_key` 是新卦例的独立 Token 归属键，同时间同六爻的不同卦例也不会混算。

`analysis` / `verdict` 始终保存首次成功原断，`analysis_question` 保存对应问题，`analysis_at` 保存首次解读完成时间，`original_analysis_id` 指向对应历史项。纯排盘原始 `question` 不因补解而覆盖。新增状态 `chart_only` 为纯排盘，`analysis_unavailable` 为尚无有效原断；有原断或已反馈的卦例追加失败记录时不降级。

`analysis_history[]` 每项对应一次 AI 请求（预审、主备解卦合并为一次请求）：

| 字段 | 含义 |
| --- | --- |
| `id` | 请求 ID，可关联 Token 账本的 run ID。 |
| `at` / `updated_at` | 请求开始与本次历史记录更新时间，ISO 8601。 |
| `status` | `pending` 处理中或异常中断尚未更新；`success` 成功；`unavailable` 拒绝/无有效问题/失败；`interrupted` 请求取消或中断。 |
| `question` | 本次实际交给模型的问题。 |
| `analysis` / `verdict` | 本次有效完整解读与独立结论；失败提示不冒充原断。 |
| `reason` | 未完成原因。 |
| `provider` / `model` | 成功解卦所用提供商配置 ID 与可取得的模型名称，缺失时不推算。 |
| `calls` | 本次逐项模型调用：`stage`、`provider`、`model`、`at`、`status`、`elapsed_ms`、`usage`。包括预审和主备调用。 |
| `usage` | 本次已知 Token 合计及未知调用数量；输入、输出、缓存、总量均分开记录，缓存包含在输入中。 |
| `legacy` | 为旧版原断补充展示的记录；缺失日期、模型、用量保持未知，不将起卦时间当成解卦时间。 |

`calls[].usage` 可能为 `null`，或部分字段为 `null`，表示供应商未报告。`not_called` 表示记账前置条件失败而没有发起模型调用，不计入调用次数和消耗。历史记录与完整排盘一起导出；导出操作不为旧数据补造新字段。

0.37.0 起普通流程先归档排盘，再调用 AI 并追加历史；纯排盘也保存，但没有有效原断时不能反馈。首次原断用于反馈，后续解读不会重置反馈闭环或积分。AI 和纯排盘容量分别受 `case_library_max_records` 与 `case_library_max_chart_records` 控制，各默认 500；按建档/最近开始解读的时间保留，编号不重复使用。

## 卦象 `cases[].cast`

| 变量名 | 类型 | 含义 |
| --- | --- | --- |
| `lines` | 整数数组 | 六爻原始值，**从初爻到上爻，自下而上**；`6` 老阴（动）、`7` 少阳（静）、`8` 少阴（静）、`9` 老阳（动）。 |
| `primary_number` / `changed_number` | 整数 | 本卦 / 之卦的六十四卦序号，范围 1–64。 |
| `primary_name` / `changed_name` | 字符串 | 本卦 / 之卦名称。 |
| `primary_symbol` / `changed_symbol` | 字符串 | 本卦 / 之卦的 Unicode 卦象符号。 |
| `primary_judgment` / `changed_judgment` | 字符串 | 本卦 / 之卦的卦辞快照。 |
| `moving_lines` | 整数数组 | 动爻爻位，`1` 为初爻、`6` 为上爻；静卦为空数组。 |
| `moving_texts` | 对象数组 | 动爻对应的本卦爻辞；每项 `position` 为爻位，`text` 为爻辞。 |
| `palace` | 字符串 | 所属八宫名称。 |
| `palace_element` | 字符串 | 本卦所属宫的五行。 |
| `primary_relatives` / `changed_relatives` | 字符串数组 | 本卦 / 之卦各爻六亲纳支标签，自下而上。之卦六亲沿用本卦宫五行作为参照。 |
| `chart` | 对象，可选 | 当时的完整排盘快照，避免日后按新规则重算而改变原盘。历史卦例可能没有。 |

### 排盘快照 `cast.chart`

| 变量名 | 类型 | 含义 |
| --- | --- | --- |
| `schema_version` | 整数 | 排盘结构版本，当前为 `1`。 |
| `calendar` | 对象 | 起卦历法信息，字段见下表。 |
| `palace` / `palace_element` | 字符串 | 本卦宫名 / 宫五行。 |
| `palace_stage` | 字符串 | 八宫阶段：本宫、一世至五世、游魂或归魂。 |
| `shi` / `ying` | 整数 | 世爻 / 应爻的爻位，范围 1–6，均指本卦。 |
| `primary` / `changed` | 对象数组 | 本卦 / 之卦六爻装卦事实，按初爻至上爻排列。 |

`calendar` 字段：

| 变量名 | 类型 | 含义 |
| --- | --- | --- |
| `status` | 字符串 | `已计算`，或未计算的具体原因，例如缺少时间、依赖不可用、历法转换失败。 |
| `rule` | 字符串 | 历法规则说明：北京时间 UTC+8，立春换年、节气交接时刻换月、零点换日。 |
| `cast_at` | 字符串 | 换算后的北京时间，带 `+08:00` 偏移。 |
| `year` / `month` / `day` / `hour` | 字符串 | 年、月、日、时干支，均不是公历数字。 |
| `month_branch` / `day_branch` | 字符串 | 月建地支 / 日辰地支。 |
| `xun` / `xun_kong` | 字符串 | 日柱所属旬 / 旬空地支。 |

计算失败时，`calendar` 可能仅包含 `status`、`rule`，不得据此补造干支。

`primary[]`、`changed[]` 共有字段：`position`（爻位）、`stem`（纳甲天干）、
`branch`（地支）、`element`（该爻五行）、`relative`（六亲）、`label`（六亲纳支显示标签）。
本卦 `primary[]` 还包含 `role`（世、应或空字符串）、`spirit`（六神，未计算时为 `—`）、
`hidden`（伏神候选对象或 `null`）。`hidden` 使用上述共有字段，候选来自本宫首卦缺失六亲，
不表示自动选定用神。之卦各爻都有装卦信息，但只有本卦原动爻发生动变，静爻不作化爻。

## 反馈与审核

`cases[].feedback[]`（以及 `legacy_rejected_feedback[]`）字段：

| 变量名 | 类型 | 含义 |
| --- | --- | --- |
| `observed_at` | 字符串 | 插件接收并保存本次反馈的时间；不一定是现实事件实际发生时间。 |
| `outcome` | 字符串 | 应验、部分应验、未应验、进行中或未分类。 |
| `text` | 字符串 | 用户提交的真实进展或结果。 |
| `answer` | 字符串 | 本次射覆揭晓答案；普通反馈通常为空。 |
| `reporter_id` | 字符串 | 反馈用户 ID。当前仅允许起卦者在所属群更新自己的卦例。 |
| `valid` | 布尔，可选 | AI 审核是否有效；`true` 计入奖励，`false` 为历史无效记录。旧反馈可能没有此字段，不能直接当作 `true` 计分。 |
| `review_reason` | 字符串，可选 | 审核理由，保存时最多 300 字。 |
| `review_command` | 对象，可选 | 通过格式和卦例身份校验的结构化审核指令，字段见下表。 |

`review_command` 与 `feedback_review.last_decision` 使用相同结构：

| 变量名 | 类型 | 含义 |
| --- | --- | --- |
| `version` | 整数 | 审核指令版本，当前为 `1`。 |
| `case_id` | 字符串 | 对应卦例的完整 `id`。 |
| `action` | 字符串 | `accept`：通过；`retry`：需要补充后重试。 |
| `valid` | 布尔 | 与动作对应：`accept` 必须为 `true`，`retry` 必须为 `false`。 |
| `outcome` | 字符串 | 上述五种结果分类之一。审核有效与预测准确是两个不同维度。 |
| `reason` | 字符串 | 审核依据，最多 300 字。 |
| `guidance` | 字符串 | 未通过时的具体补充指引，最多 300 字；通过时按协议留空。 |

`cases[].feedback_review` 字段：

| 变量名 | 类型 | 含义 |
| --- | --- | --- |
| `version` | 整数 | 审核会话结构版本，当前为 `1`。 |
| `system_prompt` | 字符串 | 本例开始审核时使用的系统提示词快照。 |
| `contexts` | 对象数组 | 审核上下文；首条原卦例快照，加最近最多 8 轮完整用户 / 助手消息。 |
| `contexts[].role` | 字符串 | 消息角色，通常为 `user` 或 `assistant`。 |
| `contexts[].content` | 字符串 | 消息正文。通常是 JSON **字符串**，外层解析后仍需再次解析才能取得其对象。 |
| `last_decision` | 对象 | 最近一轮结构化审核决定，包括未通过的 `retry`。 |
| `provider_id` | 字符串 | 最近审核使用的 AstrBot 模型提供商配置 ID，不是 API 密钥。 |

首条 `content` 内的 `original_case` 是 `id`、`question`、`cast`、`analysis`、`verdict`、
`created_at` 的原始快照。后续用户消息内的 `case_id`、`feedback`、`answer` 分别表示
卦例 ID、提交的反馈正文、射覆答案；助手消息保存审核指令 JSON 文本。
未通过的审核会话仍可保存，但不会因此写入有效正式反馈、增加积分或关闭待反馈队列。

## 存储和更新逻辑

1. **存储位置**：通过 AstrBot 的 `get_kv_data` / `put_kv_data` 读写插件独立 KV 空间，键为
   `liuyao_case_library`。插件平时不维护一个同名 JSON 磁盘文件；导出的 JSON 是该键值的文件化快照。
   KV 的底层数据库位置由 AstrBot 运行环境决定，不依赖插件代码目录或当前工作目录。
2. **创建**：开启卦例库且存储接口可用时，先保存排盘、问题和身份信息，初始分析与反馈为空。
   `id` 识别同一卦例，`serial` 用于用户查询。正常读取会为历史缺失、非正数或重复编号分配新编号；
   后续保存保留 `next_serial` 高水位。只导出时不执行这些规范化操作。
3. **分析**：调用模型前写入一条 `pending` 解读历史，完成后保存本次问题、结果、模型及用量。
   首次成功时写入 `analysis`、`verdict` 和 `analysis_question`；后续只追加历史，原断保持不变。
   编号补解严格匹配当前用户和群，并复用保存的原盘；最近原卦优先按关联 ID 查找，兼容旧记录时
   按群、用户、起卦时间和六爻值匹配。仅排盘或失败记录没有有效原断，不可反馈。
4. **反馈**：按群和起卦者定位记录。通过审核后写入反馈并闭环、更新射覆答案（如有），
   同时增加累计分数和有效反馈事件。当前每例只通过一次；未通过可沿用原编号补充。
   历史无效反馈可转存到 `legacy_rejected_feedback`。兼容写入逻辑最多保留最近 20 条正式反馈，
   这不是当前允许同例提交 20 次有效反馈。
5. **容量**：AI 与纯排盘分开限制，配置分别为 `case_library_max_records` 和
   `case_library_max_chart_records`，各默认 500，范围 20–5000。新建及追加解读时按实际建档或
   最近开始解读的时间保留各类最新记录；旧版本缺少这些时间时回退到 `created_at`。
   纯排盘首次补解后转入 AI 类别，批量纯排盘不会挤掉 AI 卦例。导出不再截断或重排。
   管理员删除仅移除对应卦例；已存在的用户登记、累计统计和独立用量账本继续保留。
6. **并发**：卦例读写共用异步锁；反馈还有每例审核锁。管理页修改通过修订值检测冲突。
   管理页响应里的 `revision` 是由记录计算的并发检查值，不是库中持久字段。
7. **检索**：历史参考按方向、卦象、问题等匹配，默认限制同群，且要求已有非明确无效、非空的反馈。
   `case_library_cross_group` 只影响检索，不缩小管理员全库导出的范围。

## 归档与迁移边界

此包包含卦例、原分析、身份标识、反馈、审核上下文、备注以及同库统计。
它不包含独立 KV 键中的用户权限、赠送和每日额度、Token 调用账本，也不包含插件配置、图片或字体。
归档完整卦例库时请选择「导出全部卦例」。

当前功能只提供导出，没有上传恢复入口；把 JSON 放回插件目录不会自动导入。
完整迁移应同时备份 AstrBot 的数据及配置。若以后编写恢复工具，应识别原始顶层格式，
保留未知字段、编号高水位和同库统计，避免直接覆盖仍在写入的数据库。
