# 第一阶段：排盘字段（0.11.0）

本阶段实现干支、月建、日辰、旬空、六神、世应、伏神及纳甲天干，接通图片、文字、Agent 输入与原卦存档。未实现结构化旺衰、冲合、自动取用及应期判断。

## 时间口径

北京时间固定 UTC+8，不依赖服务器所在时区或 Windows 时区数据库，不计算真太阳时和历史夏令时。年柱以立春精确交接时刻划分，月柱以十二节精确交接时刻划分，日柱在北京时间零点切换。晚子时（23:00–23:59）的时干由当日日干推导，日柱、旬空及六神不提前换日。

历法采用 MIT 许可的 [6tail/lunar-python](https://github.com/6tail/lunar-python)，固定版本 1.4.8；接口语义见作者的 [干支说明](https://6tail.cn/calendar/lunar.ganzhi.html)。使用 `getYearInGanZhiExact`、`getMonthInGanZhiExact`、`getDayInGanZhiExact2`、`getDayXunExact2` 与 `getDayXunKongExact2`。本插件限定公历 1900–2100 年；转换失败、依赖缺失或原时间没有时区时显式显示未计算，保留静态装卦信息。

测试的节气边界样例取自固定依赖版本的节气表：2026-02-04 04:02:08 立春、2026-03-05 21:59:00 惊蛰（北京时间）。这些测试验证接口选择和边界处理，不宣称独立完成天文历算校验。

## 装卦规则与来源

- 世应：按八宫宫序确定世爻，本宫、一至五世、游魂、归魂依次为 6、1、2、3、4、5、4、3；应爻与世爻隔两位。校核 [《增删卜易·世应章第六》](https://zh.wikisource.org/w/index.php?title=增刪卜易/6&oldid=2100291)。世应只标本卦，不把之卦自身宫序套回原卦。
- 纳甲：内乾甲、外乾壬，内坤乙、外坤癸；震庚、巽辛、坎戊、离己、艮丙、兑丁。天干表核对电子本 [录入者增订的纳甲歌与八纯卦图](https://zh.wikisource.org/zh-hans/增刪卜易#纳甲歌)，不冒称该增订为古书原文；地支对照 [《浑天甲子章第四》](https://zh.wikisource.org/zh-hans/增刪卜易/4)。六亲沿用既有规则，之卦仍以本卦宫五行为基准。
- 六神：由日干起初爻，逐爻循环。甲乙青龙、丙丁朱雀、戊勾陈、己螣蛇、庚辛白虎、壬癸玄武。校核 [《增删卜易·六神章第十八》](https://zh.wikisource.org/zh-hans/增刪卜易/18)。统一显示“螣蛇、玄武”，保留原文“滕蛇、元武”等异写于引用资料，不仅凭六神断吉凶。
- 伏神：列出本卦缺失六亲在本宫首卦的对应爻位；同一缺失六亲如有多处则保留候选，不根据变卦是否出现而删改。取自 [《增删卜易·飞伏神章第二十八》](https://zh.wikisource.org/zh-hans/增刪卜易)。天山遁的初爻伏子孙子水、二爻伏妻财寅木用于回归校核。这是候选装盘，不是自动选定用神或判断出伏。

以上为规则摘要与独立代码实现；来源核对日期 2026-10-02，数字转录并非刻本影像校勘。

## 原盘一致性与旧数据

起卦通过准入时只采集一次时间，在计次记录的 `last.chart` 保存排盘快照；完整卦例保存在 `cast.chart`，单条卦例 schema 升至 3，外层库格式保持兼容。Agent、普通命令、射覆、复解和历史重绘优先使用同一快照。模型耗时跨日不改变原盘，复解不消耗额度。

旧记录无快照时，仅在已有原时间可靠的情况下补算展示，不改原断，不把查看时间当起卦时间。没有可靠时间时，世应和伏神仍可根据卦象计算，六神等时间相关字段不补造。普通非射覆指令的完整卦例归档仍属于第三阶段。

## QQ 验证

1. 更新依赖并重载插件，在已开启六爻的群用真实具体问题起卦。可手动指定“天山遁”以观察世在二、应在五，初爻伏子孙子水、二爻伏妻财寅木。
2. 查看图中逐爻六神、世应、伏神及上方干支/月建/旬空是否清晰，普通指令成功后仍只发图。0.11.1 使用米白玉绿布局，六亲纳甲按五行着色、世应独立标记，不显示额外五行颜色图例；在 QQ 中同时检查缩略图和点开原图的可读性。
3. 发送 `/六爻 解读`，核对原时间、日柱、旬空与图片一致；重载后再复解也应一致。
4. 请 Agent 解读原卦，检查它能读取这些字段且不重新起卦；用另一个真实具体问题验证 Agent 起卦及存档。AstrBot 管理员用 `/六爻 卦例 编号` 查看，核对原图重绘保留起卦时字段。

继续遵守同一事情不连续重起和每小时三次限制；不要用“测试一下”等无事问题触发起卦。
