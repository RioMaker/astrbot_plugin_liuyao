# 六爻解卦研读笔记与古籍卦例

整理日期：2026-09-24；文档版次：1。整理者：Rio / astrbot_plugin_liuyao。

本轮重读与分类整理覆盖插件现有十个方向及共同基础；每类收录 3 个独立古籍事件，共 30 例。同一事件的复占放在同一条内，不拆开凑数。不是宣称穷尽所有易学古籍，也不是三十例的独立实验验证。

## 阅读顺序

先读 [基础与辨析](foundations.md)，再读所问的专题；有交叉问题可任意跨专题查阅。[来源与校勘](sources.md) 记录书名、数字版本、已读范围、未完成事项与许可。

## 卦例阅读约定

每例分为：出处与定位、原问与时日、卦象/关键爻、原断摘录、书载结果、整理者分析、限制。原断摘录保留所用转录字形；其余是现代摘要，不冒称古文。没有明确分开的验辞，标“未单列验辞”；没有时日、六爻图或动爻细节，明确缺失，不代填。书载凶亡、婚制与阶序原样说明历史语境，不转为对当代用户的确定性生死判断或身份定性。

古籍多是作者选录、自述；“果……”是书载，不是本插件实测。分析应比较同类问题、取用与动变结构，不因卦名相同就复制结论。不导入用户 KV 卦例库，不伪造群号、起卦人、AI 原断或实况反馈。

## Agent 读取协议

新增只读工具 `lookup_liuyao_reference(topic="")` 返回目录；传中文类别或英文键可读取任一专题全文（含三例及出处），不要求已起卦，也不受当次方向限制。`topic="基础"` 或 `foundations` 读取基础，`topic="来源"` 或 `sources` 读取校勘目录。每次一篇，需要多主题就逐次调用。

仍遵守群场景与六爻开关；公开古籍不要求管理员。此工具不读取群用户数据。用户历史卦例命令 `/六爻 卦例` 的 AstrBot 管理员权限不变。工具拒绝任意文件路径和未知类别；缺文件时明确报缺，不用其他文档冒充。

起卦原有 `data/references` 是自动注入的简版；本目录是按需查阅的扩展笔记和案例正文，不复制两份完整案例。读取不会自动发群消息，不影响图片优先、失败文字回退。更改文档后需重载插件以更新内存缓存。

## 后续校勘

本轮核对的是古书数字转录，不是刻本影像逐字校勘。待补的主要工作是：核对转录排盘/时日异文；增补《卜筮正宗》对应案例；另设失物、诉讼等类型时再收录各自至少三例；为各规则建立反例索引。没有完成的内容不得标成已读已验证。
